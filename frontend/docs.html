AUTH

Authorization

Authorization: Bearer sk_live_…

Keep sk_live_… server-side. Never expose in frontend JavaScript. Tokens are hashed with SHA-256 and verified with hmac.compare_digest.

  • Header required on every /v1/* call
  • Project resolved from API key — all queries filtered by project_id
curl http://localhost:8000/v1/verifications \
  -H "Authorization: Bearer sk_live_…"
POST

/v1/verifications

Create a single-use, 5-minute session. Enforces 20/min rate limit + max 100 pending per project.

external_user_id *metadata?

Response includes telegram_url (https://t.me/Bot?start=vfy_…) and verification_url.

POST /v1/verifications
{
  "external_user_id": "user_12345",
  "metadata": { "purpose": "signup" }
}

→ 200
{
  "id": "vrf_…",
  "status": "pending",
  "telegram_url": "https://t.me/ExampleVerifyBot?start=vfy_…",
  "verification_url": "http://localhost:8000/verify/vrf_…",
  "expires_at": "2026-09-05T10:30:00Z"
}
GET

/v1/verifications/{id}

Poll every 2–5s until terminal state. Lazy-expires on read if past expires_at.

pendingverifiedexpiredcancelled
GET /v1/verifications/vrf_abc123
→ { "id":"vrf_…", "status":"verified",
    "external_user_id":"user_12345",
    "verified_at":"2026-09-05T10:27:00Z",
    "expires_at":"2026-09-05T10:30:00Z" }
POST

Cancel & retry

POST /v1/verifications/{id}/cancel — only from pending. Retry creates a new session bound to same user.

POST /v1/verifications/{id}/retry → new vrf_ + token

POST /v1/verifications/vrf_abc/cancel
→ { "id":"vrf_abc", "status":"cancelled" }

POST /v1/verifications/vrf_abc/retry
→ { "id":"vrf_new…", "telegram_url":"…" }
POST

/internal/telegram/webhook

Telegram sends /start vfy_… here. Handler validates hash, checks expiry/usage, marks verified, upserts telegram_connections.

Idempotent per token — second use returns VERIFICATION_ALREADY_USED.

POST /internal/telegram/webhook
{
  "message": {
    "text": "/start vfy_…",
    "from": { "id": 123, "username":"john" },
    "chat": { "id": 123 }
  }
}
→ { "ok": true }
GET

/v1/telegram/connections/{external_user_id}

After verified, connection persists for notifications (future phase).

GET /v1/telegram/connections/user_12345
→ { "connected": true,
    "telegram_user_id":"123456789",
    "connected_at":"2026-09-05T10:27:00Z" }

Errors

Consistent { error: { code, message } } shape. Route-level mapping: 401 for auth, 404 for not-found, 409 for already-used, 429 for rate-limit.

{ "error": { "code": "VERIFICATION_EXPIRED", "message": "Session expired." } }
